# oh-my-opencode 源码解析总结

## 项目概述

oh-my-opencode 是一个为 OpenCode 平台设计的增强插件，旨在提供类似 Claude Code 的功能，包括专门化 AI 代理、LSP 工具、MCP 集成等。项目核心目标是实现"像人类工程师一样编码"的代理系统，通过多代理协调、丰富的开发工具和智能功能增强，提升 AI 代理的开发效率和质量。

## 核心架构

### 1. 插件架构
- **入口点**: `src/index.ts` - 主插件实现，采用 OpenCode 插件规范
- **模块化设计**: 功能按组件分离（agents, hooks, tools, features 等）
- **配置驱动**: 通过 JSON/JSONC 配置文件控制功能启用/禁用

### 2. 代理系统
- **Sisyphus**: 主协调代理（Claude Opus 4.5），负责任务规划和委派
- **Oracle**: 架构师/调试专家（GPT-5.2）
- **Librarian**: 知识管理专家（Claude Sonnet 4.5 或 Gemini 3 Flash）
- **Explore**: 代码库探索（Grok Code）
- **Frontend/UI/UX**: 前端专家（Gemini 3 Pro High）
- **Document Writer**: 文档专家（Gemini 3 Flash）
- **Multimodal Looker**: 多模态专家（Gemini 3 Flash）

### 3. 钩子系统
- **事件驱动**: 基于 OpenCode 事件系统
- **拦截机制**: 支持 `tool.execute.before/after`, `chat.message`, `event` 等拦截点
- **功能丰富**: 包括任务连续性执行器、上下文窗口监控、会话恢复等

### 4. 工具集
- **LSP 工具**: 提供完整语言服务器协议功能
- **AST-Grep 工具**: 基于语法树的代码搜索和替换
- **会话管理工具**: 会话列表、搜索、读取等
- **后台任务工具**: 异步代理任务管理

## 关键技术组件

### 1. 钩子系统 (Hooks)
- **设计模式**: 事件驱动架构
- **主要功能**:
  - `todo-continuation-enforcer`: 确保代理完成所有任务
  - `context-window-monitor`: 监控上下文窗口使用
  - `session-recovery`: 会话错误恢复
  - `comment-checker`: 防止过度评论
  - `keyword-detector`: 关键词激活功能
  - `sisyphus-orchestrator`: Sisyphus 协调器

### 2. MCP 集成
- **内置服务**:
  - `websearch`: Exa AI 网络搜索
  - `context7`: 官方文档查询
  - `grep_app`: GitHub 代码搜索
- **技能 MCP**: 支持技能自带 MCP 服务器

### 3. 技能系统
- **多源支持**: 内置技能、用户技能、项目技能、OpenCode 命令
- **MCP 集成**: 技能可自带 MCP 服务器配置
- **动态加载**: 支持运行时加载和管理技能

### 4. 配置系统
- **多级覆盖**: 项目配置 > 用户配置
- **JSONC 支持**: 支持注释和尾随逗号
- **运行时更新**: 支持配置热重载

### 5. Claude Code 兼容层
- **全功能兼容**: Hooks, Commands, Skills, Agents, MCPs
- **设置加载**: 支持 `.claude/settings.json` 等文件
- **迁移路径**: 为 Claude Code 用户提供无缝体验
